## 放进进度表（阶段 1，都是只读采集，工作量小）

按"对用户价值 / 工作量"排序。都需要在 Windows 上验证，所以今晚没动采集脚本。

| # | 检查项 | 为什么值得做 | 怎么只读地采 |
| --- | --- | --- | --- |
| 1 | **硬盘健康** | 用户最在乎、最该提前说的问题 | `Get-PhysicalDisk` + `Get-StorageReliabilityCounter`；字段为空要当作"读不到"，不能当作健康 |
| 2 | **待重启** | 很多"怪问题"的根因，且能和"关机 ≠ 重启"小知识联动 | 三个注册表位置（CBS RebootPending、WindowsUpdate RebootRequired、PendingFileRenameOperations） |
| 3 | **Secure Boot 证书更新状态** | 微软 2011 年的 UEFI 证书正在到期，时效性强 | 一个注册表值（`UEFICA2023Status`，具体路径动手前核对微软文档） |
| 4 | **系统还原是否开启** | 直接决定阶段 3 的回滚能不能依赖还原点，越早统计越好 | 注册表 / `Get-ComputerRestorePoint` |
| 5 | **BitLocker 恢复密钥提醒** | Win11 24H2 起会自动加密，换账户或换主板时没有恢复密钥 = 数据永久丢失，用户通常不知道 | `Get-BitLockerVolume`（需要管理员） |
| 6 | **可靠性监视器时间线** | 让报告能讲"从哪天开始变差、那天装了什么"，这正是 LLM 擅长讲的故事 | `Win32_ReliabilityRecords` |
| 7 | **"这台电脑被改过的地方"板块** | 最能体现"信息差"招牌：谁关了自动更新、装过 KMS 激活器、留下了优化工具的痕迹、加了非微软根证书、改了代理 / hosts、加了 Defender 排除项，汇总在一处 | 大多是只读注册表；根证书可对照微软受信任根列表 |
| 8 | 附录 A 回归测试发现的两个缺口 | 内核堆栈保护未开启（注意 Win10 和不支持的硬件上没有这个值）；单个第三方进程累计 CPU 很高（附录 A 的华为电脑管家） | 数据已经采集了，只差规则 |

## 产品与策略上的结论

- **"AI 修电脑"已经有大厂入场**（腾讯 Marvis 2026 年 9 月升级为"AI 管家"，联想、360 也在做）。我们能拉开差距的只剩：开源可审计、不常驻、证据链、可撤销、讲清楚信息差。这和"反 360"定位一致，但意味着**不要在"自动修好"上和大厂比**，而是在"讲清楚、可验证"上赢。
- **"不吓唬"要有证据**：美国 FTC 罚过两起"假体检"（Restoro / Reimage 2600 万美元、Office Depot 3500 万美元），罚的就是"干净机器也能扫出几百个问题"。建议：拿一台全新安装的 Windows 虚拟机做基准，要求 0 个问题、95 分以上，写成回归测试并在 README 公开。这是阶段 3.5 虚拟机环境的第一个用例。
- **开源协议和代码签名**：**已决定（2026-10-25）：AGPL-3.0 单一协议，纯开源，不做商业双重授权；收入只来自托管 AI 服务和打赏，不卖授权。**以后申请 SignPath Foundation 的免费代码签名；Azure 的签名服务不对中国个人开放。微软商店 2025 年 9 月起对个人开发者免费注册，MSIX 包由微软重新签名、用户看不到 SmartScreen 警告。难点是 MSIX 里放管理员服务要申请受限权限。这引出一个架构问题：**常驻的管理员服务能不能换成"需要执行操作时才提权的辅助进程"**——这样也更符合"不常驻"。建议阶段 2.3 选型时一起评估。
- **界面选型**：Tauri 在 Windows 上用的也是 WebView2（和 Edge、Electron 同为 Chromium 内核），"省内存"的优势不明显；后台已经定为 .NET，".NET 外壳 + WebView2"比 Tauri 少一门语言（Rust）。作者熟悉 Next.js，这条路线值得在 2.3 优先做小样。
- **交互**："撤销优先于确认框"有理论依据（Aza Raskin）：绿色操作执行后给"撤销"，不弹确认；红色操作要求输入确认。和现有"回滚是独立按钮"的原则一致。另一个值得学的是 Terraform 的"执行计划"：用户确认后生成带校验码的计划文件，服务只执行这份；执行前发现条件变了（报告是三天前的）就停。
- **竞品的软肋就是我们的卖点**：微软电脑管家被抓到借机推 Edge / Bing，核心卖点之一仍是"内存加速"（伪优化）。报告里坚持一句"我们不推荐任何浏览器、搜索引擎或云服务"，本身就是差异点。
- **数据政策**：Kimi 官方写明 API 数据不用于训练；DeepSeek 的条款没读到原文（第三方称默认可能用于训练、可申请退出）。进度表 1.7 模型对比时加"数据政策"一列；隐私说明写清楚报告发给了谁。以后做托管服务，按《生成式人工智能服务管理暂行办法》很可能要去地方网信办登记（阶段 4.4 前核实）。

## 第二轮（`round2.md`）

**已经落实到桌面版**：
- 操作库红线写进代码：不改 Windows 目录里的服务（禁用后蓝牙、微软账户登录、开机联网出问题的真实报告）、不卸载系统自带应用（卸载只走软件自己登记的卸载程序）、不做注册表清理（微软 KB 2563254 明确不支持）
- 回滚不依赖系统还原点（24 小时内已有还原点时新建会被跳过）：每一步自己备份改之前的状态

**放进候选版或之后**（按性价比）：

| 点子 | 说明 |
| --- | --- |
| 离线比对 LOLDrivers（只当"已知被恶意软件利用的驱动"痕迹报告，不做漏洞扫描；2026-10-25 定） | 给第三方驱动算 SHA-256，比对已知有漏洞或恶意的驱动（华为、联想、戴尔、华硕、腾讯 ACE、米哈游、BattlEye 等都在库里）。**只认哈希不认文件名**。打包前先确认 LOLDrivers 的开源协议 |
| 远控软件"无人值守"规则 | 服务方式安装且自动启动 = 开机就能被连；AnyDesk 连接记录里有密码 / 令牌登录。措辞只说"正规软件，但骗子常利用这类功能"，配反诈小知识（96110）。二手电脑、父母电脑场景价值很高 |
| 关卡 1 改成统计上站得住的标准 | 10 台 × 20 条，错 14 条（7%）的 95% Wilson 区间是 4.2%–11.4%，不能说过关。建议：模型结论 ≥ 200 条、95% 上限 < 10%；知识库 / 规则 / 模型分开统计；加盲评模式 |
| "系统被优化工具改过" | 对照干净系统的服务默认启动类型，找出被禁用的蓝牙、搜索、打印、更新等系统服务——"反 360"最有说服力的招牌之一 |
| "游戏卸了、反作弊还在" | 反作弊驱动在、游戏和启动器不在 → 卸载残留（vgk、BEDaisy、mhyprot、SGuard64 等补进知识库） |
| 健康分封顶 + 提醒 | 学 SSL Labs：严重问题封顶总分并解释原因；"现在没事、以后可能有事"的项单独一档不扣分 |
| BitLocker 恢复密钥 | 执行驱动、启动配置类操作前，确认用户已备份恢复密钥 |
| Win10 停止支持 | 按"最近一次累积更新时间"判断还有没有安全补丁 |
| .vbs 自启动 | VBScript 约 2027 年默认关闭，也是恶意软件常用手法；任何给用户的手工命令都不能再用 wmic（已从 Win11 24H2 移除） |
